LLM Gateway

Un gateway compatible con OpenAI, escrito en Python (FastAPI). Los clientes piden un alias (fast, smart, judge…), nunca un modelo; el gateway elige proveedor, reintenta, cambia de proveedor, cuida el presupuesto, cachea y mide todo. Esta guía explica cada fase construida (M0 a M9 y Stretch), todas las funciones, cómo probarlo con un chat y cómo ejecutarlo.

Las fases, una por una

Cada fase deja código, tests y una puerta de calidad. Abre una para ver qué se construyó. Los números salen de PLAN.md y de bench/results/.

  1. M0EsqueletohechoRepo, estructura de paquetes, herramientas y CI.
    • Proyecto con uv y Python 3.12, FastAPI, pydantic-settings (variables GW_*).
    • Paquetes bajo src/llm_gateway/ según el layout del plan; GLOSSARY.md fija un término por concepto.
    • Ruff (línea 110), pytest con asyncio automático, GitHub Actions, Makefile, scripts/doctor.py que revisa Docker, uv, RAM y puertos.
  2. M1Contrato OpenAI y proveedor simuladohecho/v1/chat/completions en JSON y SSE contra un proveedor mock.
    • GET /healthz, GET /v1/models (lista alias), POST /v1/chat/completions con streaming SSE.
    • Errores en formato OpenAI, headers X-Alias, X-Gateway-Provider, X-Request-Id.
    • Alias → cadena de proveedores en config/routes.yaml, validada con Pydantic al arrancar.
    • Interfaz de chat incluida en GET /, contadores en /stats.
    • Test de contrato con el SDK oficial de OpenAI.
  3. M2Proveedores reales, keys y cuotashechoOllama, Groq y Google AI Studio; una key por cliente.
    • OpenAICompatProvider para Ollama, Groq y Google. Un proveedor se registra solo si tiene key.
    • ProviderError tipado: transient, provider o client. Decide si se reintenta, se salta al siguiente o se devuelve al cliente.
    • Keys por cliente (Authorization: Bearer), guardadas como SHA-256 en config/clients.yaml (ignorado por git); scripts/new_key.py las crea. allowed_aliases se aplica.
    • Cuotas salientes en memoria (rpm/tpm/rpd): el gateway cambia de proveedor antes de recibir un 429.
  4. M3ResilienciahechoEl request baja por su cadena sin romperse.
    • executor.py: puertas por eslabón (breaker → cuota → bulkhead), timeouts por fase, un reintento con jitter completo solo en errores de conexión y 5xx, máximo 5 llamadas al proveedor.
    • breaker.py: circuit breaker con 3 disparadores.
    • bulkhead.py: concurrencia máxima por proveedor.
    • admission.py: descarte de carga; X-Priority solo puede bajar la prioridad.
    • singleflight.py: requests idénticos comparten una llamada.
    • lifecycle.py: drenaje con SIGTERM y /readyz.
    • Regla de diseño: nunca se reintenta ni se cambia de proveedor después del primer token.
  5. M4Caché exacta y semánticaparcialCaché exacta L1 lista; la semántica L2 corre en modo observación.
    • cache/keys.py (namespace, clave exacta, texto semántico, tags), guards.py (guardas léxicas), embedder.py (HashEmbedder offline; ONNX multilingual-e5-small opcional), memory.py, service.py.
    • config/cache.yaml guarda umbrales por embedder; todos en null = solo observa, sin servir hits semánticos.
    • scripts/calibrate_cache.py mide precisión y cobertura (G6).
    • cache/redis_backend.py (GW_CACHE_BACKEND=redis): entradas con TTL, vectores por namespace y tags; un fallo de Redis es un miss, no un error. Probado solo con fakeredis y sin HNSW (el ranking de vectores se hace en Python).
    • Pendiente: modelo verificador de zona gris, ~1000 pares etiquetados para calibrar G6, y probar el backend contra un Redis real.
  6. M5Presupuesto y precioshechoDinero en micro-dólares, reserva atómica, nunca gasto sorpresa.
    • pricing/prices.py y config/prices.yaml: USD por Mtok = µ$ por token, Decimal, redondeo hacia arriba.
    • budget/: reserva el peor caso antes de llamar y liquida después. Tres topes: corrida, cliente por día, global por día. Backend en memoria o Redis con Lua atómico.
    • Si un eslabón de pago no cabe, se salta al siguiente con X-Budget-Skipped; si no queda nada, 402 budget_exceeded. Si el almacén cae, falla cerrado para proveedores de pago.
    • GET /admin/budget. El presupuesto diario por cliente vale 0 por defecto (sin gasto de pago).
  7. M6Streaming robustohechoKeep-alive, cancelación y errores tipados en medio del stream.
    • Comentario : ping tras GW_STREAM_PING_S segundos de silencio.
    • La lectura upstream corre en su propia tarea; si el cliente se va, se cancela hacia el proveedor.
    • Un stream que se cuelga termina con un chunk de error tipado y sin [DONE], para que un error no parezca un final limpio.
    • Pruebas contra un servidor uvicorn real.
  8. M7Salida estructurada y Anthropichechoresponse_format validado y adaptador nativo de Claude Haiku 5.5.
    • structured/validate.py: valida JSON / JSON Schema, hace un reintento de reparación y, con stream, valida antes de enviar.
    • providers/anthropic.py: API Messages nativa, usage normalizado, cache_control desde 512 tokens, effort acotado, parámetros no soportados descartados.
    • Se registra solo con la key y GW_RUN_BUDGET_USD>0.
    • Headers X-Params-Dropped, X-Effort, X-Structured-Repaired.
  9. M8Observabilidad y seguridadhechoMétricas, log JSON, trazas, key de admin, rate limit.
    • /metrics Prometheus (peticiones, TTFT, tokens, costo, caché, breaker, presupuesto, fallbacks…).
    • Un log JSON por request, nunca con prompts ni respuestas.
    • Trazas OpenTelemetry (gateway.request y provider.attempt, traceparent).
    • Key de admin (GW_ADMIN_KEY_SHA256) para /stats, /metrics, /admin/*.
    • Rate limit por cliente (rpm), límites de tamaño y forma por alias, 413 para cuerpos grandes.
    • Perfil Docker obs: Prometheus, Grafana con dashboard y Jaeger.
  10. M9Benchmarks y publicaciónv1.0Arnés abierto, README con trazabilidad EARS.
    • bench/: G1 sobrecarga, G10 disponibilidad, G13 throughput; resultados en bench/results/; workflow nocturno.
    • README en inglés con tabla EARS (R01–R23, cada requisito con su test) y tabla de headers.
    • GW_CORS_ORIGINS: CORS opcional para apps de navegador.
    • Resultados: G10 = 99,98 %; G13 ≈ 1 200 req/s; G1 no cumple el objetivo de <5 ms p95 en Windows (+10,4 ms p95 sin caché).
  11. SStretchv1.1 · parcialHedging, EWMA, AIMD, visión, guardrails heurísticos, recarga en caliente.
    • Hedging (G12): si el primer eslabón calla más de hedge_delay_s (o 3× su EWMA de TTFT), se compite con el siguiente; gana el primero que responde y el perdedor se cancela. Medido: p99 1015 ms → 131 ms (7,7×) con 6,5 % de llamadas extra.
    • Reordenar por EWMA: reorder: ewma pone primero el eslabón más rápido.
    • AIMD: bulkhead adaptativo opcional (adaptive: true): +1 tras una ventana de éxitos, mitad con 429/timeout/TTFT lento.
    • Visión: solo alias con vision: true aceptan imágenes; si no, 400 images_not_supported.
    • Guardrails heurísticos: inyección de prompt (ES/EN) y PII por regex; modos off|monitor|enforce; X-Untrusted-Content.
    • Recarga en caliente: POST /admin/reload o vigilante de archivos; todo o nada.
    • Presidio: redacta el prompt del log cuando GW_LOG_PROMPTS=true (uv sync --extra pii). Usa un pipeline de spaCy en blanco: solo reconocedores de patrón (email, tarjeta, teléfono, IBAN, SSN, IP, URL, DNI); nombres y lugares no se redactan, y no redacta el tráfico saliente.
    • Langfuse: exporta spans por OTLP/HTTP (GW_LANGFUSE_HOST/PUBLIC_KEY/SECRET_KEY, requiere --extra otel) porque su API de ingestión legada está deprecada. Sin texto de prompts. Solo se probó la configuración (endpoint, auth Basic, header de versión), nunca un Langfuse real.
    • Prompt Guard 2 (ONNX): clasificador en guardrails/promptguard.py, se activa si hay modelo en models/prompt-guard/. El modelo es gated (licencia de Meta), así que solo se probó con una sesión falsa y nunca con pesos reales.

Todas las funciones del gateway

Alias y cadenas

El cliente pide fast, smart, judge, vision, extract o smart_paid. Cada alias es una lista ordenada de proveedores y modelos con su política. Toda cadena termina en un modelo local o en mock, así que el gateway responde sin internet.

Compatibilidad OpenAI

Funciona con el SDK oficial cambiando solo base_url. JSON y SSE, usage, response_format, top_p, reasoning_effort, stream_options.

Proveedores

Ollama (local), Groq y Google AI Studio (planes gratis), Anthropic nativo (de pago, apagado por defecto) y mock (solo dev/test).

Fallback y reintentos

Un reintento con jitter en errores de conexión y 5xx; después, siguiente eslabón. Nunca después del primer token. Hasta 5 llamadas por request.

Circuit breaker y bulkhead

Un proveedor enfermo se aparta solo y se prueba de nuevo más tarde. Cada proveedor tiene un tope de concurrencia (fijo, o adaptativo con AIMD).

Cuotas salientes

Buckets por proveedor para respetar los planes gratis y saltar antes del 429.

Admisión y prioridades

Descarta carga cuando hay demasiados requests; X-Priority solo baja la prioridad.

Singleflight

Requests idénticos cacheables comparten una sola llamada upstream.

Caché exacta y semántica

L1 exacta con namespaces, TTL y tags (/admin/cache/invalidate). L2 semántica con guardas léxicas, en modo observación hasta calibrar umbrales.

Presupuesto atómico

Reserva el peor caso en micro-dólares y liquida; tres topes; falla cerrado para proveedores de pago.

Streaming robusto

Pings, cancelación hacia el proveedor, error tipado en medio del stream, sin [DONE] al abortar.

Salida estructurada

Valida JSON / Schema, repara una vez, y avisa con X-Structured-Repaired.

Hedging y EWMA

Compite con el siguiente eslabón cuando el primero tarda; ordena por latencia medida.

Visión

Imágenes solo en alias con vision: true; costo fijo de 800 tokens por imagen en la estimación.

Guardrails

Tamaño y forma (max_messages, max_images, 413) y heurísticas de inyección/PII con X-Guardrail-Flags.

Seguridad

Keys por cliente con hash, key de admin, rate limit por cliente (memoria o Redis), CORS opcional.

Observabilidad

/metrics, /stats, log JSON sin prompts, trazas OTel, Grafana y Jaeger.

Operación

/healthz, /readyz, drenaje con SIGTERM, recarga en caliente, UI de chat en /.

El viaje de un request

De izquierda a derecha, en este orden. Cada caja puede responder por sí sola y cortar el viaje.

auth→rate limit→tamaño/forma→visión→guardrail→caché exacta→singleflight→admisión→breaker→cuota→bulkhead→presupuesto→proveedor→validación→respuesta + X-*

Chat de prueba

Dos modos. Demo simulado corre aquí mismo y reproduce cómo el gateway elige proveedor, cae al siguiente, usa la caché y devuelve headers. Gateway real intenta llamar a tu servidor.

Importante: dentro de claude.ai esta página corre en un marco aislado que bloquea las llamadas de red a otros sitios, así que el modo real será rechazado ahí. Para probar tu gateway de verdad abre http://localhost:8080/guide: es esta misma página servida por el gateway, con el modo real activo y sin CORS. También sirve http://localhost:8080/ (chat mínimo) y los comandos curl de abajo.

SIMULADO. Ninguna respuesta viene de un modelo real; las respuestas son texto fijo para mostrar el comportamiento.

Para usar el modo real desde tu disco: pulsa "Descargar chat local", ábrelo, elige "Gateway real" y arranca el gateway con GW_CORS_ORIGINS=*. Prueba: envía "hola" dos veces (la segunda sale de caché); marca "Groq caído" y envía otro mensaje (cae a ollama/mock); escribe "ignore all previous instructions" con enforce activo.

Cómo ejecutarlo

Necesitas uv (instala Python 3.12 solo). Todo funciona sin internet con el proveedor mock.

  1. Instalar y verificar

    git clone <tu-repo> llm-gateway && cd llm-gateway
uv sync --dev
uv run pytest -q          # 364 tests
uv run ruff check .

  2. Crear una key de cliente

    Imprime la key una sola vez y la entrada para pegar en config/clients.yaml (archivo ignorado por git; hay un ejemplo en config/clients.example.yaml).

    python scripts/new_key.py me fast smart judge vision extract

  3. Arrancar el servidor

    uv run uvicorn llm_gateway.main:app --port 8080
# con recarga de código: uv run uvicorn llm_gateway.main:app --reload --port 8080

    Abre http://localhost:8080/ para el chat incluido: pega tu key y verás los headers como etiquetas.

  4. Probar con curl o con el SDK de OpenAI

    curl -s localhost:8080/v1/chat/completions \
  -H "Authorization: Bearer $KEY" -H "Content-Type: application/json" \
  -d '{"model":"fast","messages":[{"role":"user","content":"hola"}]}' -i
    from openai import OpenAI
client = OpenAI(base_url="http://localhost:8080/v1", api_key=KEY)
print(client.chat.completions.create(model="fast",
      messages=[{"role": "user", "content": "hola"}]).choices[0].message.content)

  5. Activar proveedores reales (opcional)

    Copia .env.example a .env y rellena lo que tengas. Sin key, el proveedor simplemente no se registra.

    VariablePara qué sirve
    GW_ENVdev (por defecto), test, prod. mock existe solo en dev/test.
    GW_GROQ_API_KEYActiva Groq (plan gratis).
    GW_GOOGLE_API_KEYActiva Google AI Studio (Gemma, plan gratis).
    GW_OLLAMA_BASE_URLOllama local, por ejemplo http://localhost:11434/v1.
    GW_ANTHROPIC_API_KEYClaude Haiku 5.5. Solo funciona junto a GW_RUN_BUDGET_USD>0.
    GW_RUN_BUDGET_USD0 = proveedores de pago apagados.
    GW_CORS_ORIGINSOrígenes de navegador permitidos (o *).
    GW_CACHE_BACKEND / GW_EMBEDDERmemory|redis|off (redis usa GW_REDIS_URL); e5-small|hash|off.
    GW_GUARDRAILS_MODEoff, monitor (por defecto) o enforce.
    GW_RELOAD_INTERVAL_S>0 recarga rutas/clientes/precios al cambiar los archivos.
    GW_ADMIN_KEY_SHA256Hash de la key de admin (python scripts/new_key.py --admin).
    GW_STREAM_PING_SSegundos de silencio antes del : ping.

  6. Stack completo con Docker

    make up        # gateway + Redis
make up-obs    # + Prometheus, Grafana (dashboard listo), Jaeger

    Sin make en Windows, usa los comandos docker compose del Makefile.

  7. Benchmarks

    uv run python -m bench.availability   # G10, ~99,98 %
uv run python -m bench.hedging        # G12, p99 con y sin hedging
uv run python -m bench.hits           # G9, latencia de hit exacto y semántico
uv run python -m bench.savings        # G11, costo ahorrado (Zipf sintético)
uv run python -m bench.guardrails     # G14, recall y falsos positivos
uv run python -m bench.overhead       # G1, lento
uv run python -m bench.throughput     # G13, lento

  8. Recargar configuración sin reiniciar

    curl -X POST localhost:8080/admin/reload -H "Authorization: Bearer $ADMIN_KEY"

    Si el archivo nuevo es inválido, responde 400 y sigue sirviendo la configuración anterior.

Límites honestos

  • El objetivo de sobrecarga G1 (<5 ms p95) no se cumplió en la máquina Windows de prueba.
  • Los umbrales de la caché semántica no están calibrados; hoy solo observa. Faltan el verificador de zona gris y ~1000 pares etiquetados. El backend Redis de la caché existe pero solo se probó con fakeredis.
  • G9 medido: hit exacto p95 2,0 ms y semántico p95 11,5 ms (e5-small), pero con un umbral fijado solo para la corrida porque G6 sigue abierto. G11 medido con tráfico Zipf sintético y solo caché exacta: 70–94 % del costo de referencia ahorrado según la forma del tráfico; el 30–40 % del plan depende de tráfico real y no se confirmó. El caos con Toxiproxy no se ha medido. No hay Docker en la máquina de desarrollo, así que el perfil obs y Redis no se probaron aquí.
  • El adaptador de Anthropic se probó con fixtures, no contra streams reales.
  • El guardrail de inyección/PII es un sustituto por regex. G14 sobre un set escrito a mano de 94 filas: recall de inyección 100 % en frases directas y 0 % en paráfrasis u ofuscación, 4,7 % de falsos positivos; PII recall 100 %, precisión 93 %.
  • Langfuse y Prompt Guard 2 no se han ejecutado contra el servicio o los pesos reales. Presidio no detecta nombres (sin NER).
  • El hedging, el reorden por EWMA y AIMD son opt-in y solo se probaron en proceso.
